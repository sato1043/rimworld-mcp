# 火災の場所を tool で読めるようにする

## 目的

火災が起きたとき、LLM がその場所を知り、消火に向かわせるか、放っておいてよいかを
判断できるようにする。

TASK0016 の実機シナリオの途中（2026-09-27）で、LLM は「火災が 6 件あるが、場所が
分からない」と報告した。

## 目標（起票時の案）

- 火災の場所を、脅威の読み出し（`get_threats`・overview の `threats`）で返す
- 基地に関わる火災と、マップの遠くの火災を見分けられる手がかりを添える
- 既定の出力の量を、火災が多いとき（山火事等）にも抑える
- upstream へ送れる変更と、この fork の変更に依存する変更を、別のブランチに分ける
- スキル `rimworld-play` の `references/tools.md` から、火災の場所を探してマップを
  総なめにしない旨の項目を、新しい読み方に合わせて書き換える（fork ローカルの変更として
  分ける）

## 非目標

- 消火を指示する tool（`assign_job` の既存の範囲を超えるもの）
- 火災以外の脅威の読み出しの変更

## 問題

- **火災は件数しか返らない。** `GameStateReader.GetThreats` と `GetAlerts` は、
  `ThingsOfDef(ThingDefOf.Fire)` のうちマップに置かれた物を数え、`activeFires` に件数
  だけを入れる（2026-09-27 に読んだ）。敵は `position` つきで返すので、場所を返す形の
  先例は同じ応答の中にある
- **場所を探す手段が実用にならない。** `get_cells_info` は 1 回 32×32 マスまでで、
  250×250 のマップを総なめにすると約 64 回の呼び出しになる
- **件数には、基地に関わらない火災も入る。** 山火事や、マップの端で燃える物も数える。
  入植者が自分から消すのは居住エリアの火災だけである（推論。1.6 で確かめていない）
  ので、居住エリアの内外を添えると判断しやすい
- **燃えている入植者や死体についた火も、同じ `Fire` として数えている可能性がある**
  （推論）。場所だけでなく、何が燃えているかを返すかを決める
- 山火事では火が数百に増えうる。1 件ずつ返すか、近い火をまとめて範囲で返すか、上限を
  置くかを決める。上限で切るなら、切ったことを応答に出す（TASK0020 と同じ問題）
