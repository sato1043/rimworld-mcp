# 数の少ない品の在庫を tool で確かめられるようにする

## 目的

LLM が、数の少ない品（AI ペルソナコア等）がマップにあるかを、利用者に頼まずに確かめられる
ようにする。

TASK0016 の実機シナリオ「1 サイクル」で、宇宙船のコンピューターコアに要る AI ペルソナ
コアの在庫を `get_things` で確かめられず、LLM は利用者にゲーム画面での確認を頼んだ
（2026-09-27）。

## 目標（起票時の案）

- 品目を指定して、その品の数を確かめられるようにする。数が少なく上位に入らない品も
  対象にする
- 既定の出力の量は、今と同じ程度に保つ
- upstream へ送れる変更と、この fork の変更に依存する変更を、別のブランチに分ける

## 非目標

- 倉庫ゾーンごとの中身（`get_stockpile_contents` が扱う）
- 入植者の持ち物・キャラバンの荷物の在庫

## 問題

- **`get_things` は合計数の多い順に 60 種で切る。**
  `GameStateReader.GetThings` は、運べる物（`HaulableEver`）のうち、マップに置かれて
  死体でない物を品目ごとに合計し、`OrderByDescending(totalCount).Take(60)` で返す
  （2026-09-27 に読んだ）。1 個だけの品は、品目が 60 種を超えるコロニーでは漏れる
- **切られたかどうかが応答に出ない。** 60 件目で切ったのか、品目が 60 種しか無いのかを、
  呼ぶ側は見分けられない
- 形の候補は、品目の defName を引数で受けて絞る・切った件数を応答に添える・上限を
  引数にする、などである。`get_animals` の `race`（TASK0006）が、既定を絞ったまま 1 種を
  指定して引ける先例になる
- 数えるのはマップに置かれた物だけで、入植者の持ち物やキャラバンの荷物は入らない
  （`t.Spawned`）。呼ぶ側がこれを知らないと「無い」と誤って読む

## 裁定記録

- **起票**（2026-09-27・ユーザー）: TASK0016 の実機シナリオの途中で、在庫の tool が
  60 種しか返さない件を改善できるかを問い、できるなら起票すると指示した
