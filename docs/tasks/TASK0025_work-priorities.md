# 入植者の仕事の優先度を tool で変えられるようにする

## 目的

LLM が、入植者の仕事の優先度（どの仕事をどの順で受け持つか）を、利用者に頼まずに
変えられるようにする。

TASK0016 の実機シナリオの途中（2026-09-27）で、LLM は Engie の「電工」を有効にしたかった
が tool が無く、2 サイクル続けて利用者に画面での操作を頼んだ。

## 目標（起票時の案）

- 入植者と仕事の種類を指定して、優先度（無効・1〜4）を設定できるようにする
- 入植者がその仕事をできない（体質・経歴で不可）ときは、理由つきで断る
- upstream へ送れる変更と、この fork の変更に依存する変更を、別のブランチに分ける
- スキル `rimworld-play` の `references/tools.md`「tool に無い操作」から仕事の優先度の
  行を消す（fork ローカルの変更として分ける）

## 非目標

- 仕事の種類の並び順・細かい仕事（WorkGiver）単位の設定
- 予定表（`set_schedule_hour` が扱う）

## 問題

- **優先度は読めるが、変えられない。** `get_pawn_work` は
  `pawn.workSettings.GetPriority` で優先度を読む（`GameStateReader` 467 行目付近。
  2026-09-27 に読んだ）。書き込むコマンドは `CommandExecutor.cs` に無い
- **数字の優先度が効くかは、ゲームの設定で変わる**（推論。1.6 で確かめていない）。
  「手動で優先度を設定する」が無効なら、ゲームは有効・無効だけで扱う。その設定を読むか、
  応答で示すかを決める
- 入植者が不可の仕事（`get_pawn_work` の `incapable`）を指定されたときの扱いを決める
- 仕事の種類の名前は、defName（`Doctor` 等）で受けるか、表示のラベルでも受けるかを
  決める。`get_pawn_work` の応答にどちらが出ているかを先に確かめる

  無くて困った操作」のうち、仕事の優先度を起票すると指示した
