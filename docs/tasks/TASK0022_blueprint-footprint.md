# 設計図が占めるマスを、置く前に知れるようにする

## 目的

LLM が、大きさが 1×1 でない建物の設計図を、向きと占めるマスを見込んだうえで 1 回で
置けるようにする。

TASK0016 の実機シナリオの 2 サイクル目（2026-09-27）で、LLM は宇宙船の冷凍睡眠棺
（`Ship_CryptosleepCasket`）を 4 回置こうとし、1 回も置けなかった。

## 目標（起票時の案）

- 設計図を置く前に、建物の大きさ・向き・位置から、占めるマスの範囲と、置けるかどうかと
  その理由を確かめられるようにする
- 置いたときの応答に、占めるマスの範囲を添える
- 向きで意味が変わるマス（頭部・作業をする側のマス等）があれば、そのマスを返す
- upstream へ送れる変更と、この fork の変更に依存する変更を、別のブランチに分ける

## 非目標

- 複数のマスへまとめて置くこと（壁の列など）
- 床とゾーンを置くこと（`place_blueprint` の非対応。TASK0016 の `tools.md` に記載）

## 問題

- **置けなかった 4 回の応答は次のとおり**（プレイのセッションの会話の記録
  `9c1e41c4-9e26-4977-95b5-553af7ddd14f.jsonl` から読んだ）
  - (156,67)・向きの指定なし: 「頭部側が船体骨格に接するよう配置してください」
  - (156,67)・West: 「この場所は既に塞がっています」
  - (157,67)・West と (156,67)・East: 頭部側が船体骨格に接していない
- **応答は占めるマスを返さない。** 成功すると基点のマス（`position`）・向き・素材だけを
  返す（`CommandExecutor.Build`）。失敗するとゲームの `CanPlaceBlueprintAt` の理由の文を
  返すが、どのマスが問題かは返さない
- **占めるマスを手で割り出すと、取り違える。** 同じセッションで LLM は、反応炉（6×7）の
  四隅のマスを読んで範囲を推し量った。その結果を攻略知識の候補にしたとき、x と z の
  範囲を取り違えた文（「x148〜153・z131 ではなく z67〜73」）を示した（2026-09-27）
- **大きさと向きから占めるマスを出す規則は、ゲームが持つ**（推論。`GenAdj.OccupiedRect`
  と、偶数の大きさの向きによる基点のずれ。1.6 で確かめていない）。Mod でその関数を
  呼べば、LLM が規則を覚えずに済む
- 頭部の概念は、ベッドと冷凍睡眠棺にある（推論）。どの建物がどのマスを特別に扱うかを
  一覧にする方法を決める必要がある
- 置く前に確かめる形は、`place_blueprint` に試すだけの引数を足すか、読み出しの tool を
  新しく足すかで分かれる。後者は TASK0012 の annotations で読み出しに分類できる
- 応答のラベルに見えない文字（ゼロ幅スペース）が混ざっていた（`耐圧冬眠カプセル` の
  `冬眠` と `カプセル` の間に U+200B）。扱いは TASK0014 が受け持つ

## 裁定記録

- **起票**（2026-09-27・ユーザー）: TASK0016 の実機シナリオの途中で、大きさが 1×1 で
  ない部品の向きと占めるマスを見込んで操作する方法があるかを問い、ありそうなら起票すると
  指示した
- **x と z の取り違え**（2026-09-27・ユーザー）: 新しく起票せず、本作業の根拠に
  含める。原因は占めるマスを手で割り出したことで、本作業の目標がそれを不要にする。
  候補を示す前に出典と照らす手順は、TASK0016 のスキルに足した
