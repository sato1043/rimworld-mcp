# 建物の電源を tool で入れたり切ったりできるようにする

## 目的

電力が足りないとき、LLM が利用者に頼まずに、要らない建物の電源を切れるようにする。

TASK0016 の実機シナリオ「1 サイクル」で、LLM は電力の赤字（消費が発電を 950 W 上回る）を
見つけた。しかし電源の切り替えを行う tool が無く、蓄電が減ったら利用者に切ってもらう、
という計画を立てた（2026-09-27）。

## 目標（起票時の案）

- 建物を ID で指定して、電源を入れる・切るを指示できるようにする
- 切り替えられる建物を、既存の読み出し（`get_buildings`）から見つけられるようにする
- upstream へ送れる変更と、この fork の変更に依存する変更を、別のブランチに分ける
- スキル `rimworld-play` の `references/tools.md`「tool に無い操作」から電源の行を消す
  （fork ローカルの変更として分ける）

## 非目標

- 電力網の配線（電線の設置・切断）
- 発電機の燃料の補給

## 問題

- **電源を切り替えるコマンドが無い。** `MCP/Source/MCP/CommandExecutor.cs` に該当が
  無く、`get_buildings` は `CompPowerTrader.PowerOn` を読むだけである（2026-09-27 に
  読んだ）
- **ゲームでの切り替えは、入植者が建物まで歩いて行う作業である**（推論。1.6 で
  確かめていない）。スイッチを持つ建物は `CompFlickable` を持ち、画面の切り替えは
  「切り替えの指定」を置き、入植者がそれを実行すると考えている。tool で指定を置くか、
  即座に切り替えるかを決める必要がある。即座の切り替えは、ゲームの手順を飛ばすズルに
  あたりうる（TASK0016 の裁定: ズルの tool は利用者の許可を得てから使う）
- スイッチを持たない建物もある（推論）。その建物を指定されたときの応答を決める
- 書き込みの tool なので、TASK0012 の annotations の分類の対象になる

## 裁定記録

- **起票**（2026-09-27・ユーザー）: TASK0016 の実機シナリオの途中で、電源の切り替えを
  tool で実現できるかを問い、できるなら起票すると指示した
