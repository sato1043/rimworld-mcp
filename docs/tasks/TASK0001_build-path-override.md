# ビルドの RimWorld 導入先を上書き可能にする

**この作業書は実装の完了後に書いた。** 計画の節は実装時に下した判断を再構成したもので、
着手前に確定していたものではない。経緯は「裁定記録」に残す。

## 目的

`MCP.csproj` の `HintPath` が GOG 版の導入先を直書きしており、それ以外の環境では
ファイルを編集しない限りビルドできなかった。開発機は Steam 版で、実際にビルドできない
状態からこの作業が始まった。導入先を外から与えられるようにして、リポジトリを編集せずに
ビルドできる状態にする。

## 目標

- RimWorld の導入先をリポジトリの外から与えられるようにする
- 導入先が誤っているとき、何をどう直せばよいかが分かる形でビルドを止める
- 既定値を変えず、既存の環境（GOG 版）での挙動を保つ

いずれも提供要求（SREQ）を採番しない。知覚ゲートを通らないためである ── 機能設計記述の
外部仕様に知覚項目を加えず、ビルド構成だけを変える作業である。

## 非目標

- 同梱 DLL の扱い（追跡の是非・依存の固定方法）。TASK0002 が扱う
- `CONTRIBUTING.md` のビルド節の更新。fork 固有の記述のため別の変更で扱う
- RimWorld 本体のバージョン差の吸収

## 問題

- 開発機に RimWorld の GOG 版が無く、Steam 版だけが在る
- 既定値を変えると upstream の作者の手元で挙動が変わる。変えずに上書きできる必要がある
- 導入先が誤ったときの既定の失敗は、参照解決の失敗による大量の型未解決エラーになる。
  原因のパスもプロパティ名も現れない

- [x] CP6 の第三者視点レビューを実施するかをユーザーが裁定する

## 概要設計

MSBuild のプロパティで導入先を受け、参照の `HintPath` をそこから組み立てる。

- `RimWorldDir` — 導入先のルート。`Condition="'$(RimWorldDir)' == ''"` を付けて既定値を
  現状の GOG パスに保つ。MSBuild は同名の環境変数をプロパティとして読むので、
  `-p:RimWorldDir=...` と環境変数が同じ口になる
- `RimWorldManagedDir` — `$(RimWorldDir)` 配下の `RimWorldWin64_Data\Managed`。
  2 つの `HintPath` が共有する
- `CheckRimWorldDir` — `BeforeTargets="BeforeBuild"` で `Assembly-CSharp.dll` の存在を
  確かめ、無ければ探したディレクトリと直し方を添えて `Error` を出す

`Directory.Build.props` へ切り出す案も採りうるが、ファイルが 1 つ増える割に得るものが
無い。プロパティ 1 つで足りる。

## 実装計画

1. `MCP.csproj` にプロパティ 2 つと `CheckRimWorldDir` を足し、`HintPath` を差し替える
2. `README.md` のビルド節を書き換える
3. 3 通りの入力でビルドを検証する


## 作業記録

- 着手時、`dotnet build` が NuGet の復元で失敗した（NU1100）。原因は `MCP.csproj` では
  なく、この機械の利用者レベル `NuGet.Config` の `<packageSources>` が空で、パッケージ
  フィードが 1 つも登録されていなかったこと。マシンレベル・リポジトリ内の設定も無く、
  nuget.org への疎通は正常だった。利用者がフィードを登録して解消した
- 復元が通らない段階でも、`CheckRimWorldDir` を単独で実行すればガードだけは検証できた。
  復元後に同じ入力で再検証し、結果が一致することを確認した
- 検証の途中で `RestorePackagesWithLockFile` を試し、`packages.lock.json` が
  Lib.Harmony 2.4.2 / Newtonsoft.Json 13.0.4 を contentHash つきで固定することを
  確認した。この作業の範囲外のため生成物は削除し、論点を TASK0002 へ送った
