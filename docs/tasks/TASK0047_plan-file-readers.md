# 方針ファイルを読む側が、無人のサイクルの書いた文をどう扱うかを決める

## 目的

無人のサイクルが方針ファイルへ書いた文が、より広い tool を持つ読み手（対話のセッション・
開発のセッション）に、利用者の確認を経ずに指示として働かないようにする。

TASK0040 は、サイクルの Write と Edit を方針ファイルに絞った。サイクルが保存できる先は
方針ファイルだけになり、信頼の境界は、方針ファイルを読む側へ移った。読む側の扱いは
決まっていない。

## 目標（起票時の案）

- 方針ファイルの読み手を列挙し、読み手ごとに、どの節を方針として読み、どの節をデータと
  して読むかを決める
- 利用者の承認を表す節（「開発者向けの書き足しの候補」の「承認済み」）へ、サイクルが
  書いた文が承認として通らない形にする
- 決めた扱いを、読み手のスキルの手順（`rimworld-play`）と、サイクルの定義へ書く
- 扱いが守られていることを、機械で見られる範囲で確かめる

## 非目標

- サイクルが書けるファイルの範囲（TASK0040 が持つ）
- サイクルが読める範囲（TASK0040 の非目標と同じ）
- 親のセッションの扱い。親は方針ファイルを読まない（`rimworld-autoplay` の SKILL.md）

## 問題

出典は、TASK0040 の第三者視点レビュー（2026-10-12）の指摘（security-offensive M3・
security M5）である。どれも手順とスクリプトの読み取りで、モデルが実際に従うかは測って
いない。

- **データとして扱う定めは、tool の応答にしか無い。** `rimworld-play` は、tool の応答の
  文字列をデータと定める。方針ファイルは「始める前に」で方針として読み、同じ定めの対象に
  入っていない
- **経路が在る。** ゲーム内の文字列（letter・名前）→ 無人のサイクル → 方針ファイル →
  次のサイクルと、利用者が後で開く対話のセッション。対話のセッションはコマンドを走らせる
  tool を持つ
- **承認を表すのは節の見出しだけである。** 方針ファイルの「開発者向けの書き足しの候補」の
  「承認済み」は、利用者が承認した文面の置き場所で、開発のセッションがそこからスキル
  （追跡下の指示文）へ反映する。サイクルはその節へ書ける
- **本文の指示は守りではない。** 「環境」を書き換えない・「経過のメモ」のズルの許可、は
  サイクルの定義の本文の指示で、書き込みを止める仕組みは無い
- **ほかのコロニーの方針ファイルも書ける。** TASK0040 の裁定「コロニーの絞り込み」は、
  判定を状態のファイルに依らせないために、すでに在るどのコロニーの方針ファイルも許す。
  開いていないコロニーには、照合の控え（`plan.md.prev`）が取られない
- **利用者が読む節は、利用者が見分ける。** 「利用者に頼むこと」へ積まれた頼みは、利用者が
  読んで動く。親は方針ファイルを読まず、件数だけを示す（TASK0040 の CP6 で受容。
  security-offensive M4）

## 裁定記録

- **起票**（2026-10-12・ユーザー）: TASK0040 の CP6 の束 G のうち 2 件（security-offensive
  M3・security M5）を、新しい作業書へ送る（エージェントの推奨を採った）。読み手の列挙と
  扱いの線引きに新しい設計が要るためである

## stakeholder 未裁定の残課題

- 優先度の 4 軸と `drive`
- 対話のセッションが、方針ファイルのどの節までを方針として読むか（すべてをデータとすると、
  サイクルが共有する記憶として働かなくなる）
- 承認を、節の見出しのほかの何で表すか（利用者だけが書ける場所へ移す・照合の控えと
  比べる等）
