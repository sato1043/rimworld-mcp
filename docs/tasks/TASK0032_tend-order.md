# 負傷者の看護を tool で確かめて命じられるようにする

## 目的

負傷者の看護が進まないとき、LLM が原因（医療の方針・医者の手の空き）を tool で読み、
医者に看護を命じられるようにする。命に関わる出血を、利用者の画面の操作を待たずに
止められるようにする。

無人の運用（TASK0018）の実機（2026-09-29）で、失血で倒れた入植者（失血 0.457・
出血率 1.15、医療用ベッド）が 4 サイクルを通して看護されなかった。医者の 2 人は
「医者」の優先度が 1 だったが、消火と自分の安静を先に選んだ。LLM は、医療の方針を
画面で確かめ、医者に看護を命じるよう利用者に頼んだ。

## 目標（起票時の案）

- 入植者ごとの医療の方針（「治療放棄」から「治療する(最先端医薬品まで使用)」までの
  5 段階）を、読み出しの応答に加える
- 医療の方針を変える命令と tool を足す
- 医者と患者を指定して看護を命じる命令と tool を足す。ゲームの右クリックの
  「{0}を看護する」と同じ判定（医者の可否・看護の要否・医療の方針・到達の可否）を通し、
  できないときは理由を返す。薬はゲームと同じ選び方で選ぶ
- upstream へ送れる変更と、この fork の変更に依存する変更を、別のブランチに分ける
- スキル `rimworld-play` に、看護が進まないときの確かめ方と命じ方を書き足し、
  `references/tools.md`「tool に無い操作」から医療の方針の行を消す（fork ローカルの
  変更として分ける）

## 非目標

- 手術（`queue_medical_operation` が扱う）
- 医療用ベッドの設定と、患者をベッドへ運ぶこと（`rescue_pawn` が扱う）
- 仕事の優先度の変更（TASK0025 が扱う）
- 派閥・囚人・家畜ごとの医療の方針の初期値の変更

## 問題

- **命じる口が無い。** tool に看護は無い（2026-09-29 に tool の一覧で確かめた）。
  `assign_job` に JobDef `TendPatient`（`Defs/JobDefs/Jobs_Work.xml`）を渡せば始め
  られる可能性はある（推論。確かめていない）が、薬を選ばず、看護の可否の判定も通さない。
  スキルは `assign_job` をズルに当たる tool として許可を要するものに挙げ、
  サブエージェント `rimworld-cycle` はこれを使えない（`.claude/agents/rimworld-cycle.md`
  の禁止の一覧）
- **医療の方針を読めない。** `MCP/Source/MCP` に `medCare` を読む箇所が無い
  （2026-09-29 に grep で確かめた）。`get_medical` は看護の要る傷病を返すだけである。
  方針が「治療放棄」なら医者は看護しない（推論）ので、原因の切り分けに要る
- **医者が看護より消火・安静を選ぶのは、仕事の種類の並び順による**（推論）。
  `WorkTypes.xml` の `naturalPriority` は消火 1400・瀕死 1350・医者 1300・病人 1200
  である（2026-09-29 に読んだ）。優先度の数字が同じなら並び順の上が先に選ばれる
- **使えそうな API がある。** `WorkGiver_Tend`・`GoodLayingStatusForTend`・
  `HealthAIUtility.FindBestMedicine`・`Pawn_JobTracker.TryTakeOrderedJob`・
  `playerForced`・`MedicalCareCategory` の名前がアセンブリにある（2026-09-29 に
  文字列で確かめた。振る舞いは確かめていない）
- **命じた看護が、医者自身の安静や消火に割り込まれるか**を確かめる必要がある（未確認）
- 医者自身が倒れている・患者へ届かないときの断り方を決める
- 実機でしか確かめられない。看護の要る入植者がいるセーブの状態が要る
