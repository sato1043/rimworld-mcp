# プレイする LLM がゲームの日本語表示の語で書けるようにする

## 目的

プレイする LLM（スキル `rimworld-play`・サブエージェント `rimworld-cycle`）が、方針
ファイル・報告・利用者への頼みごとを、ゲームの日本語表示と同じ語で書けるようにする。
利用者が頼みごとを読んで、画面のどこを操作すればよいかをすぐ引けるようにする。

無人の運用（TASK0018）の実機（2026-09-29）の方針ファイルで、LLM はゲームの表示と違う
語を使った。「珍品商」（ゲームでは「エキゾチックトレーダー」）・「AI ペルソナコア」
（「AI人格コア」）・「気分」（「心情」）・「請求書」（「加工」）である。

## 目標（起票時の案）

- プレイする LLM が、ゲームの概念の日本語表示を引ける手段を持たせる（用語表、または
  引くための道具）
- スキルの「語はゲームの日本語表示に合わせる」という規則と、その手段を結びつける
- スキル自身の文面を、ゲームの日本語表示の語へ揃える
- 手段が正しい語を返すことを、確かめる検査を置く

## 非目標

- MCP の tool の応答を日本語にすること
- 方針ファイルに既に書かれた語の書き換え（利用者のセーブごとのファイルである）
- Mod が足した語の網羅（「電工」のような Mod の仕事の種類）

## 問題

- **規則はあるが、手段が無い。** スキルは「語はゲームの日本語表示に合わせる」と
  3 か所で求める（`references/tools.md`・`references/basics.md`・
  `references/advanced.md`）。語を引く手段は書かれていない。サブエージェント
  `rimworld-cycle` の定義には、この規則が無い（2026-09-29 に grep で確かめた）
- **スキル自身が規則から外れている。** `references/basics.md` は「気分」を 2 行で使い、
  「心情」を使っていない（2026-09-29 に数えた）
- **方針ファイルで外れた語の行数**（2026-09-29 に数えた）: 「珍品商」4 行・
  「ペルソナ」6 行・「気分」6 行・「請求書」5 行。対して「心情」0 行・「加工」1 行
- **tool の応答の語は英語と見られる。** 方針ファイルに英語の表示（`calming down`）が
  引用されており、LLM は英語のラベルを自分で訳していると見られる（推論）。
  ゲームは翻訳を Def の読み込み時に `label` へ当てるので、応答が英語ならゲームは
  英語で動いている（推論。言語の設定は確かめていない）。**利用者の画面が英語なら、
  日本語表示に合わせる規則そのものが画面と食い違う。** 先に確かめる
- **語の出典はゲームの言語ファイルである。** `Data/Core/Languages/Japanese (日本語).tar`
  の `DefInjected`（Def のラベル）と `Keyed`（画面の文言）から引ける（2026-09-29 に
  引いた）。例: `Crafting.labelShort` は「工芸」、`MedicalCareCategory_NoCare` は
  「治療放棄」
- **言語ファイルの文をリポジトリへ写してよいかを決める。** ゲームのデータであり、
  この fork は公開されている。写さずに、手元のインストールから引く道具にする案もある
- **何を載せるかを決める。** 言語ファイル全体は大きい。プレイで使う語（仕事の種類・
  必要・トレーダーの種類・医療・建物・品物等）に絞るか、defName で引かせるかを決める
