# 利用者の頼みでサイクルを起こす

## 目的

無人で回している間に、利用者が「今サイクルを起こして」と頼んだら、監視スクリプトの
合図を待たずに 1 サイクルを起こせるようにする。起こし方は決まった手順とし、親が
その場で合図を組み立てずに済むようにする。

## 目標（起票時の案）

- 利用者の頼みで起こすときの、起こす理由（合図の語彙）と、その合図の 1 行を出す口を
  持つ。起動文は、TASK0018 の決まりどおり機械が出した行だけで組む
- 利用枠の判定と `usage.log` が、利用者の頼みで起こしたサイクルを、ほかの理由と
  見分けて数える
- サイクルの印・監視スクリプトの状態（見回りの起点・戦闘の保持）と食い違わない

## 非目標

- 利用者の返事の中身をサイクルへ渡すこと（TASK0038 が扱う）
- 状況の変化から自動で起こすこと（TASK0037 が扱う）

## 問題

- **スキルの手順には、合図無しでサイクルを起こす道が無い。** 親は監視スクリプトの
  合図ごとにだけサイクルを起こし、起動文は機械が出した行だけで組む
  （`rimworld-autoplay` の SKILL.md）。2026-09-30 の実機（TASK0018 のシナリオ
  「襲撃が 2 回の起床にまたがる」）で、利用者が「今サイクルを起こして」と頼んだ。親は
  見回り（`patrol`）の形の合図を自分で組み、中に「利用者の依頼で起こした（監視
  スクリプトの合図ではない）」と書いて起こした。親は頼みに応じたと利用者へ説明した
- **その場の組み立ては、記録と判定を取り違える。** 親は `usage_gate.py` に
  `--reason patrol` を渡したので、`usage.log` にはこのサイクルが見回りとして残った。
  合図の 1 行は tick を持たず、監視スクリプトが出す形とも違う
- **起きなかった間が長くなりうる。** 同じ実機では、倒れた敵が残ったまま `all_clear`
  （tick 35473445）が出た後、敵がいないので追いの合図は来ず、次に来るのは見回り
  （既定で 60000 tick。実時間では約 17〜77 分）だった。その間に利用者は頼まれた操作を
  3 件片付け、「次のサイクルはいつ始まる？」と尋ねてから起こすよう頼んだ
- **監視スクリプトとの関係が決まっていない。** 監視スクリプトは、サイクルが閉じた
  時点から見回りと追いの間隔を数える。親が別の経路で起こしても印は置くので、数え方は
  保たれる（推論。実機の 1 回だけを見た）
