# トレーダーから品物を tool で買えるようにする

## 目的

LLM が、コロニーを訪れたトレーダー（キャラバン・軌道上の商船）の品物と値段を読み、
tool で買えるようにする。AI人格コアのようにクリアに要る品を、トレーダーの滞在中に
利用者を待たずに買えるようにする。

無人の運用（TASK0018）の実機（2026-09-29）で、LLM は「エキゾチックトレーダーが
来たら AI人格コアを買う」ことを利用者に頼んだ。AI人格コアは宇宙船のコンピューター
コア（`Ship_ComputerCore`）の材料である（`Buildings_Ship.xml` の `costList`。
2026-09-29 に読んだ）。

## 目標（起票時の案）

- トレーダーの品物を、defName・数・値段つきで読めるようにする
- トレーダーと品物・数を指定して、銀と引き換えに買う命令と tool を足す。銀が
  足りない・品物が無いときは理由を返す
- 取り消せない取引の誤呼び出しを防ぐ形（確認の引数・前提の検査）を持たせる
- upstream へ送れる変更と、この fork の変更に依存する変更を、別のブランチに分ける
- スキル `rimworld-play` の `references/tools.md`「tool に無い操作」から、交易の行を
  足した範囲で直す（fork ローカルの変更として分ける）

## 非目標

- キャラバンで他の拠点へ出向く交易（TASK0017 の非目標と同じ）
- 通信機でトレーダーを呼ぶこと・贈与
- トレーダーの到着を待つ仕組み。到着の後のサイクルで方針ファイルの頼みごとを見る
  運用は TASK0018 の側で扱う

## 問題

- **買う口が無い。** tool に交易は無く、`get_traders` は読み出しだけである
  （2026-09-29 に確かめた）
- **品物の読み出しが足りない。** `GameStateReader.GetTraders` は地上のトレーダーの
  品物をトレーダー本人の `inventory` から読み、ラベルと数だけを 20 種まで返す。
  値段と defName を返さない。軌道上の商船は品物を返さない（2026-09-29 に読んだ）。
  キャラバンの品物は荷物を運ぶ動物も持つので、本人の `inventory` だけでは欠ける
  （推論）。`Pawn_TraderTracker` と `get_Goods` の名前がアセンブリにある
- **ゲームの取引は画面を通る。** 画面では交渉役の入植者がトレーダーへ歩いて行き
  （JobDef `TradeWithPawn`）、取引の画面（`Dialog_Trade`）で数を決める。tool で
  取引するなら、交渉役を歩かせるか、歩かせずに取引を成立させるかを決める。後者は
  ズルに当たりうる。`TradeSession.SetupWith`・`Tradeable.AdjustTo`・
  `TradeDeal.TryExecute`・`TradeUtility.ColonyThingsWillingToBuy` の名前が
  アセンブリにある（2026-09-29 に文字列で確かめた。振る舞いは確かめていない）
- **軌道上の商船は、通信機と軌道交易ビーコンを要する**（推論）。銀がビーコンの範囲に
  あるかも条件になる
- **値段は交渉役の社交で変わる**（推論）。誰を交渉役にするかを決める
- **取引は取り消せない。** 銀を失う
- 実機でしか確かめられない。トレーダーが滞在しているセーブの状態が要る
