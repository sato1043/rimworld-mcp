# RimWorld を MCP で遊ぶためのスキルを置く

## 目的

LLM が rimworld-mcp の tool でコロニーを運営するとき、毎回同じ手順と知識から始められる
ようにする。プレイで分かった攻略知識を、出典と確度をつけて溜めていけるようにする。

## 目標

- プロジェクトスキル `.claude/skills/rimworld-play/` を置き、git で追跡する
- 1 サイクルの手順（ポーズ → 観察 → 割り込みの確認 → 方針との照合 → 指示 → 報告）を
  スキルに書く。手番はポーズのまま返す（CP6 の裁定）
- セーブごとのコロニー方針ファイルの置き場所・節・読み書きの時機を決め、雛形をスキルに
  持たせる。方針ファイル自体は追跡しない
- MCP の操作知識のうち、tool の説明文に無いもの（呼ぶ順序・出来事の位置の持ち方・欠けて
  いる操作）を書く
- 基本攻略（1.6・DLC なし）を、項目ごとに出典と確度をつけて書く
- 応用攻略の節を立て、クリアの経路（宇宙船の打ち上げ・クエスト「宇宙への旅」）とその
  前提を書く
- 攻略知識を書き足す手順（セッションの終わりに候補を示し、承認された文面だけを方針
  ファイルへ溜め、開発のセッションがスキルへ反映する）をスキルに書く

## 非目標

- クリアに要る tool（打ち上げ・セーブ・キャラバンの出発）の追加（TASK0017）
- 外側のループ・無人での長時間の運用・実時間の待ち合わせ（TASK0018）
- DLC（Royalty・Ideology・Biotech・Anomaly・Odyssey）の攻略
- Mod と MCP サーバーのコードの変更
- セーブごとの方針ファイルを git で追跡すること（裁定 2026-09-27）
- upstream へ送ること

## 問題

- **`.gitignore` が `.claude/` と `**/.claude/` を除外している。** 除外された
  ディレクトリの下は、否定のパターン（`!`）では追跡へ戻せない（gitignore の仕様）。
  `.claude/skills/` だけを戻すには、除外の書き方を変える必要がある
- **攻略知識の正しさを機械で確かめる手段が無い。** 学習済みの知識は 1.6 と以前の版の差を
  区別できない。出典を持たない項目は、誤っていても正しい顔で残る。一次情報として、
  インストール先の `Data/Core/Defs` の XML（研究の前提・建物の数値）が使える
  （2026-09-27 確認。Steam 版 1.6.4871、`Data` の下は `Core` だけ）
- **ゲーム内の時間を進める tool が無い。** `set_time_speed` で速めて実時間で待つしかない。
  対話セッションでは、待つ間に届いた脅威を拾えない
- **クリアに要る操作が tool に無い。** 打ち上げ・セーブ・キャラバンの出発は
  `mcp_server/main.py` に無い（2026-09-27 grep）。スキルでは、これらを利用者の手操作へ
  回すと書くしかない
- **スキルはプロンプトである。** 書いた手順どおりに LLM が動くかは、実際に回すまで
  分からない
- この fork の開発用の文脈（`CLAUDE.md`・`CONTRIBUTING.md`・SessionStart の案内）が
  プレイ中のセッションにも載る。置き場所を裁定したときに受け入れた

### スキルの構成

`SKILL.md` は呼ばれるたびに全文が読み込まれる。そこで、`SKILL.md` には手順だけを置き、
知識は `references/` に分けて、要るときに読ませる。

- `SKILL.md`: いつ使うか・1 サイクルの手順・割り込みの判定・書き足しの手順・参照先
- `references/tools.md`: tool の説明文に無い操作知識。説明文の事実は写さず、それを
  前提にスキルがどう動くかを書く。目的別の tool の選び方、`get_events` の位置の持ち方、
  出力の量を抑える目安、欠けている操作と受け持つ作業書
- `references/basics.md`: 序盤から中盤の基本。住居・食料・研究の順・仕事の優先度・
  温度・医療・気分・防衛
- `references/advanced.md`: 応用の節と、クリアの経路。宇宙船は研究の前提と部品を Defs
  から引き、クエスト「宇宙への旅」は届く時機とキャラバンが要ることを書く
- `references/colony-plan-template.md`: 方針ファイルの節の雛形
- `scripts/check_skill.py`: 攻略の項目の書式と、backtick の中の名前を照合する

利用者へ示す語は、ゲームの日本語表示（言語ファイル）に合わせる（CP6 の裁定）。

### 1 サイクル

1. `set_pause` で止める
2. 観察する。`get_colony_overview` を 1 回呼び、詳細は要る tool だけを呼ぶ
3. 割り込みを確かめる。方針ファイルに残した位置を `since` に渡して `get_events` を呼び、
   `more` なら続きを読む。命に関わる letter（脅威・負の出来事・死亡・脅威を伴う
   クエスト）、期限のある選択、overview の threats・alerts があれば、方針の照合より先に
   対応する。
   読めなかった節は個別の tool で読み直す。対応の後も 6・7 を通る
4. 方針ファイルを読み、今の状態と照らして次の指示を決める
5. 指示する
6. 方針ファイルを更新する（進捗・次にやること・出来事の位置）
7. ポーズのまま報告し、ターンを終える。利用者が「進めて」と頼んだら速度を決めて進める
   （見ていない間にゲームを進めないため。実時間の待ち合わせは TASK0018）

割り込みと数える letter の型名（`ThreatBig`・`NegativeEvent` 等）は、Defs の
`LetterDefs` から引いて確かめた。

### コロニー方針ファイル

本体のチェックアウトの `.claude/play/<コロニー名>/plan.md` に置き、worktree を消しても
残るようにする。プレイは本体のチェックアウトで起動したセッションで回す。セッションが
本体でない（`git worktree list --porcelain` の最初の worktree と
`git rev-parse --show-toplevel` が違う）なら、方針ファイルを読み書きせずに止まって
利用者へ伝える。隔離された worktree のセッションは本体へ書けないためで、別の置き場所を
探すと方針が割れる（裁定 2026-09-27。CP6 で再判定）。

コロニー名は tool から取れない（TASK0019 で取れるようにする）。`.claude/play/` の下の
一覧を示して選んでもらい、新しいコロニーのときだけ名前を尋ねる。ディレクトリ名に使えない
文字を含む名前は、別名を決めてもらう。節は、長期方針・研究の道筋・基地の配置・クリアの
計画・次にやること・出来事の位置・書き足しの候補・経過のメモとする。サイクルの初めに
読み、終わりに書く。追跡しないので、書くのに承認は要らない。

### 攻略知識の書式

ファイルの冒頭で対象（1.6・DLC なし）と、最初に読んだ版を宣言する。後から足す項目で
版が違うときだけ、その項目に版を書く。各項目の形の正本は `SKILL.md`「攻略知識を
書き足す」で、`check_skill.py` がその形（出典の種別・確度の値域・Wiki だけなら高に
しない）を照合する。

出典は Defs（一次情報）を先に引き、Defs に無いこと（進め方・定石）は RimWorld Wiki
（二次情報）の URL を引く。1 回だけの実機の観測は確度を「低」とする。実機の出典には
Mod の有無を書き、コロニー名は書かない（追跡するファイルへセーブの名前を写さないため）。

### 書き足しの手順

セッションの終わりか、利用者に頼まれたときに、候補を並べる。各候補は書き込む文面
（項目そのもの）と書き込む先のファイルを持つ。利用者が承認した文面を、方針ファイルの
「書き足しの候補」へそのまま写し、決まらなかった候補は保留として残す。プレイの
セッションはスキルを変えない。スキルへの反映は、開発のセッションが topic ブランチで
行い、`check_skill.py` を回す（プレイは `develop` の上の本体で回るので、そこで書くと
直接のコミットを避けられないため。CP6 の裁定）。このセーブだけの事情は、方針ファイルの
ほかの節へ書く。

`check-ignore` は 1 パスずつ終了コードで判定する。1 行目だけが 1（除外されない）で、
残りの 4 行は 0（除外される）ならよい。複数のパスを 1 回で渡すと、どれか 1 つが除外
されるだけで 0 になるので合否に使えない。`check_skill.py` は exit 0 で合格、1 で違反、
2 で照合器が信用できない。
