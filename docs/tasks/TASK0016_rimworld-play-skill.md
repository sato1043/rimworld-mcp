# RimWorld を MCP で遊ぶためのスキルを置く

## 目的

LLM が rimworld-mcp の tool でコロニーを運営するとき、毎回同じ手順と知識から始められる
ようにする。プレイで分かった攻略知識を、出典と確度をつけて溜めていけるようにする。

## 目標

- プロジェクトスキル `.claude/skills/rimworld-play/` を置き、git で追跡する
- 1 サイクルの手順（ポーズ → 観察 → 割り込みの確認 → 方針との照合 → 指示 → 進める）を
  スキルに書く
- セーブごとのコロニー方針ファイルの置き場所・節・読み書きの時機を決め、雛形をスキルに
  持たせる。方針ファイル自体は追跡しない
- MCP の操作知識のうち、tool の説明文に無いもの（呼ぶ順序・出来事の位置の持ち方・欠けて
  いる操作）を書く
- 基本攻略（1.6・DLC なし）を、項目ごとに出典と確度をつけて書く
- 応用攻略の節を立て、クリアの経路（宇宙船の打ち上げ・ジャーニーオファー）とその前提を
  書く
- 攻略知識を書き足す手順（セッションの終わりに候補を示し、承認されたものだけを書く）を
  スキルに書く

## 非目標

- クリアに要る tool（打ち上げ・セーブ・キャラバンの出発）の追加（TASK0017）
- 外側のループ・無人での長時間の運用・実時間の待ち合わせ（TASK0018）
- DLC（Royalty・Ideology・Biotech・Anomaly・Odyssey）の攻略
- Mod と MCP サーバーのコードの変更
- セーブごとの方針ファイルを git で追跡すること（裁定 2026-09-27）
- upstream へ送ること

## 問題

- **`.gitignore` が `.claude/` と `**/.claude/` を除外している。** 除外された
  ディレクトリの下は、否定のパターン（`!`）では追跡へ戻せない（gitignore の仕様）。
  `.claude/skills/` だけを戻すには、除外の書き方を変える必要がある
- **攻略知識の正しさを機械で確かめる手段が無い。** 学習済みの知識は 1.6 と以前の版の差を
  区別できない。出典を持たない項目は、誤っていても正しい顔で残る。一次情報として、
  インストール先の `Data/Core/Defs` の XML（研究の前提・建物の数値）が使える
  （2026-09-27 確認。Steam 版 1.6.4871、`Data` の下は `Core` だけ）
- **ゲーム内の時間を進める tool が無い。** `set_time_speed` で速めて実時間で待つしかない。
  対話セッションでは、待つ間に届いた脅威を拾えない
- **クリアに要る操作が tool に無い。** 打ち上げ・セーブ・キャラバンの出発は
  `mcp_server/main.py` に無い（2026-09-27 grep）。スキルでは、これらを利用者の手操作へ
  回すと書くしかない
- **スキルはプロンプトである。** 書いた手順どおりに LLM が動くかは、実際に回すまで
  分からない
- この fork の開発用の文脈（`CLAUDE.md`・`CONTRIBUTING.md`・SessionStart の案内）が
  プレイ中のセッションにも載る。置き場所を裁定したときに受け入れた

## 概要設計

### 置き場所と追跡

```
.claude/
  skills/rimworld-play/        追跡する（fork ローカル）
    SKILL.md
    references/
      tools.md                 MCP の操作知識
      basics.md                基本攻略
      advanced.md              応用攻略・クリアの経路
      colony-plan-template.md  方針ファイルの雛形
  play/<コロニー名>/plan.md    追跡しない（セーブごとの方針）
  tmp/                         追跡しない（既存）
```

`.gitignore` は次の形へ変える。ルートの `.claude/` は中身を除外し、`skills/` だけを戻す。
サブディレクトリの下の `.claude/` は従来どおり除外する。効くかどうかは `git check-ignore`
で確かめる（到達基準）。

```
/.claude/*
!/.claude/skills/
/*/**/.claude/
```

### スキルの構成

`SKILL.md` は呼ばれるたびに全文が読み込まれる。そこで、`SKILL.md` には手順だけを置き、
知識は `references/` に分けて、要るときに読ませる。

- `SKILL.md`: いつ使うか・1 サイクルの手順・割り込みの判定・書き足しの手順・参照先
- `references/tools.md`: tool の説明文に無い操作知識。目的別の tool の選び方、
  `get_events` の位置の持ち方、`detail=True` を要るときだけ使うこと、欠けている操作と
  その代わりの手操作
- `references/basics.md`: 序盤から中盤の基本。住居・食料・研究の順・仕事の優先度・
  温度・医療・気分・防衛
- `references/advanced.md`: 応用の節と、クリアの経路。宇宙船は研究の前提と部品を Defs
  から引き、ジャーニーオファーはキャラバンが要ることを書く
- `references/colony-plan-template.md`: 方針ファイルの節の雛形

### 1 サイクル

1. `set_pause` で止める
2. 観察する。`get_colony_overview` を 1 回呼び、詳細は要る tool だけを呼ぶ
3. 割り込みを確かめる。方針ファイルに残した位置を `since` に渡して `get_events` を呼ぶ。
   脅威の letter と、overview の threats・alerts があれば、方針の照合より先に対応する
4. 方針ファイルを読み、今の状態と照らして次の指示を決める
5. 指示する
6. 方針ファイルを更新する（進捗・次にやること・出来事の位置）
7. `set_time_speed` で進める。対話セッションではここでターンを終え、利用者が次の
   サイクルを頼む（実時間の待ち合わせは TASK0018）

脅威と数える letter の型名（`ThreatBig` 等）は、Defs の `LetterDefs` から引いて確かめる。

### コロニー方針ファイル

`.claude/play/<コロニー名>/plan.md` に置く。コロニー名の取り方は実装時に
`get_game_state` の応答で決める。節は、長期方針・研究の道筋・基地の配置・クリアの計画・
次にやること・出来事の位置・経過のメモとする。サイクルの初めに読み、終わりに書く。
追跡しないので、書くのに承認は要らない。

### 攻略知識の書式

ファイルの冒頭で対象（1.6・DLC なし）を宣言する。項目ごとには版を書かず、版で違う点が
あるときだけ書く。各項目は次の形にし、機械で「出典」と「確度」の欠けを数える。

```
- <主張>
  - 出典: 実機（YYYY-MM-DD・<コロニー名>） / Defs（<パス>） / <URL> / 推論
  - 確度: 高 / 中 / 低
```

出典は Defs（一次情報）を先に引き、Defs に無いこと（進め方・定石）は RimWorld Wiki
（二次情報）の URL を引く。1 回だけの実機の観測は確度を「低」とする。

### 書き足しの手順

セッションの終わりか、利用者に頼まれたときに、候補を並べる。各候補は主張・出典・確度・
書き込む先のファイルを持つ。利用者が承認した候補だけを書く。このセーブだけの事情は
スキルでなく方針ファイルへ書く。
