# ストーリーテラー・難易度・Mod の構成を tool で読めるようにする

## 目的

LLM が利用者に尋ねずに、今のゲームのストーリーテラー・難易度・有効な Mod を読めるように
する。

TASK0016 のスキルは、セーブ全体の前提を方針ファイルの「環境」に書く。攻略知識は Mod の
無い Core の Defs によるので、どの Mod が入っているかと、どの難易度で遊んでいるかが、
知識を当てはめてよいかの前提になる。今は Mod をゲームの設定ファイルから読み、ストーリー
テラーと難易度を利用者に尋ねている（TASK0018 のステップ 8j）。

## 目標（起票時の案）

- 今のゲームのストーリーテラーと難易度を、defName と表示名で tool から読めるようにする
- 有効な Mod の一覧を、packageId と名前で tool から読めるようにする
- TASK0016 のスキルの「環境を調べる」を、tool から読む形へ直す（設定ファイルを読む手順と
  利用者に尋ねる手順を外す）
- upstream へ送れる変更と、この fork の変更に依存する変更を、別のブランチに分ける

## 非目標

- ストーリーテラー・難易度・Mod の構成を変えること
- Mod が変えた仕組みを攻略知識へ反映すること

## 問題

- **ストーリーテラーと難易度を返す tool が無い。** `get_game_state`（`/state`）は tick・
  速度・季節・バイオーム・マップの広さ・人数・資産だけを返す
  （`GameStateReader.GetWorldState`）。Mod のソースに、ストーリーテラー・難易度・Mod の
  一覧を読む箇所は無い。2026-10-10 に読んで確かめた
- **利用者の答えからは defName が決まらないことがある。** 2026-10-10 の方針ファイルの
  作り直しで、利用者は「フェーベ・チラックス」「世はこともなし」と答えた。本体の日本語の
  表示は `Phoebe` が「フェーベ ベースビルダー」、難易度は「ピースフル」「コミュニティ
  ビルダー」等で、どれとも一致しない。有効な Mod に翻訳の Mod があり、画面の語が本体と
  違うとみられる（推論）
- **設定ファイルは名前を持たず、置き場所が OS で変わる。** `ModsConfig.xml` の
  `activeMods` は packageId だけを持つ。置き場所は Windows だけを確かめた。セッションが
  リポジトリの外のファイルを読むことにもなる
- **尋ねて得られるのは要約で、一覧にならない。** 同じ作り直しで、利用者は「操作を
  改善するものが主で、ストーリーを変えるものは無い」と答えた。設定ファイルの一覧は
  38 件で、動物・客・仕事の種類を足す Mod の packageId も並ぶ（中身は確かめていない）。
  数十件の名前を利用者に書き出してもらうのは現実的でない
- 読む API は、`Find.Storyteller` の `def` と `difficultyDef`、
  `ModsConfig.ActiveModsInLoadOrder` が候補である（推論。`Assembly-CSharp.dll` に
  `difficultyDef` と `ActiveModsInLoadOrder` の文字列が在り、実在しない名前は 0 件で
  あることだけを 2026-10-10 に確かめた。振る舞いは実装の段で確かめる）
- 足す先は、`get_game_state` の応答へ欄を足すか、新しい tool を足すかで分かれる。Mod の
  一覧は数十件になるので、毎サイクル読む応答へ足すと出力が増える。コロニー名
  （TASK0019）も同じ分かれ目を持つ
