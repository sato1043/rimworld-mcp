# 利用者の返事をサイクルへ渡す

## 目的

無人で回している間に、利用者が頼まれた操作を片付けたことや、頼みへの返事を、次の
サイクルへ確実に届ける。片付いた頼みが方針ファイルに残り続け、サイクルが頼み直したり、
片付いていない前提で判断したりすることを防ぐ。

## 目標（起票時の案）

- 利用者が親のセッションへ伝えた「片付けた」「こうしてほしい」を、親が攻略の判断を
  せずに次のサイクルへ渡す口を持つ
- サイクルは渡された返事を読み、「利用者に頼むこと」の該当する項目を消すか、返事に
  沿って対応を改める
- 親の文脈は、返事 1 件につき決まった量しか伸びない（TASK0018 の目的を保つ）

## 非目標

- 選択肢を持つ letter に答える口（TASK0030 が扱う）
- 利用者の返事を親が解釈して、方針ファイルを直に書き換えること

## 問題

- **返事を渡す経路が無い。** 親は起動文に決まった 3 行（コロニー・合図・前回の照合）
  だけを渡し、自分の言葉を足さない。方針ファイルも読み書きしない（`rimworld-autoplay`
  の SKILL.md）。2026-09-30 の実機で、利用者が「Pena と Ileana の Doctor の優先度を
  上げた」と親へ伝えたが、親はサイクルへ伝えられず、方針ファイルの項目を 1 行消すことを
  決まりの外の操作として申し出るしかなかった
- **片付いたかをサイクルが自分で確かめられるとは限らない。** 雛形は「片付いたら消す」
  と書く（`colony-plan-template.md`）が、確かめる手段は頼みの種類で違う。仕事の優先度は
  `get_pawn_work` で読めるが、tool に無い操作の結果は読めないものがある（未調査）
- **起動文は機械が出した行だけで組む。** 起動文に利用者の言葉を足すと、親が読み替えない
  という TASK0018 の決まりと、起動文を決まった形に保つ守り（実機で、親が自分の判断で
  通知を送ろうとした）に触れる。返事は利用者の言葉のまま、形を決めて渡す必要がある
- **返事は利用者の入力で、サイクルに対しては指示として働く。** 渡す範囲（頼みへの
  返事に限るか、新しい指示も受けるか）を決める必要がある

## 裁定記録

- **起票**（2026-09-30・ユーザー）: 無人の運用中に、利用者が頼みを片付けたことを
  サイクルへ伝える経路が無いことを、課題として起票する

## stakeholder 未裁定の残課題

- 返事の置き場所（起動文の 4 行目・方針ファイルの節・別のファイル）
- 渡す範囲（頼みへの返事だけか、新しい指示も含むか）
- 返事が届くまでの間の扱い（次の合図を待つか、返事で 1 サイクルを起こすか）。利用者の
  頼みで起こす口は TASK0041 が扱う
