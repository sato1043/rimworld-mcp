# サイクルに渡る tool の範囲を、無人の運用の前に確かめる

## 目的

無人で回す前に、サイクルのサブエージェントが、利用者の許可を要する tool とコマンドを
走らせる tool を実際に持っていないことを、運用のたびに確かめる。

TASK0018 の外側のループは、誰も確認しない間にサイクルを起こす。サイクルの定義
（`.claude/agents/rimworld-cycle.md`）は、持たせる tool を一覧で限り、ズルに当たる tool と
取り消せない操作の tool を除く。定義どおりに tool を絞るのは Claude Code の本体で、
絞り込みが効かなくなれば、無人のサイクルが `deconstruct` 等を呼べる。

## 目標（起票時の案）

- rimworld-autoplay の「始める前に」に、サイクルの定義を探りの起動文で 1 回起こす確かめを
  足す
- 判定はスクリプトが行う。サブエージェントの transcript から、本体が渡した tool の一覧と
  tool の呼び出しの結果を読み、除いた tool とコマンドを走らせる tool が無いことを照らす
  （ユーザー裁定 2026-10-10）
- 探りの起動文は、スクリプトが rimworld-play の SKILL.md の一覧から作る。名前をスキルの
  文へ写さない
- 照らせなかったとき（transcript が見つからない・一覧の記録が無い・形が読めない）は、
  合格にせず止まる
- 確かめが落ちたら、運用を始めずに利用者へ伝えて止まる
- TASK0018 の実機シナリオの「準備の確認」（利用者が起動文を手で渡す）を、この確かめで
  置き換える

## 非目標

- 除いた tool を実際に呼んで確かめること（呼べてしまったときに実害が出る）
- MCP の tool が動くかの確かめ（監視スクリプトの自己点検が持つ）
- サイクルの Write と Edit の届く範囲（TASK0040 が持つ）

## 問題

- **今の照合は実行時を見ていない。** `check_cycle_agent.py` は、サイクルの定義の
  `tools`・`disallowedTools` と、rimworld-play の SKILL.md の一覧と、`main.py` の tool を
  照らす。本体がその定義どおりに tool を渡すかは見ていない
- **スキルはその性質に寄りかかっている。** rimworld-autoplay の「始める前に」の 4 は
  「サイクルの定義が除いた tool は、許しても呼べない」と書く。確かめたのは、TASK0018 の
  「準備の確認」を手で回した回だけである（2026-09-29。8g の回し直しでもう 1 回回す）
- **本体の振る舞いは予告なく変わる。** サブエージェントの Write が `REPORT` 等で始まる
  名の `.md` を断ることは、実機で失敗するまで分からなかった（TASK0018 の裁定記録
  「報告のファイル」。2.1.283 と 2.1.286 で確かめた）
- **自己申告は判定に使えない。** 「準備の確認」の起動文は、13 個の名前が自分の tool の
  一覧にあるかをサイクル自身に答えさせる。09-29 に証拠として使えたのは、transcript の
  最初の `deferred_tools_delta`（`mcp__rimworld__*` が 77 個で、`main.py` の 87 個との差が
  除く 10 個と一致）と、`Bash` の呼び出しの失敗（「No such tool available: Bash」）
  だった。`PowerShell` と `Monitor` は呼び出しでは確かめていない
- **transcript の形は公開の仕様でない。** サブエージェントの transcript は
  `<セッション>/subagents/agent-<id>.jsonl` に在り、2026-10-04 の運用（2.1.286）の
  transcript にも `deferred_tools_delta` の `addedNames` が在る（2026-10-10 に 1 本を
  読んで確かめた）。形が変われば読めなくなるので、読めないときに止まる側へ倒す必要がある
- **呼び出しの失敗は、モデルが呼ぶかに左右される。** 2026-10-10 の「準備の確認」
  （2.1.293・`claude-sonnet-5-5`）では、サブエージェントが `Bash` は一覧に無いとして
  呼び出しを試みず、失敗の記録が残らなかった。同じ回のサブエージェントの置き場所には
  `agent-<id>.prefix.json` が在り、その `toolNames` が遅延でない tool の名前（7 個）を
  持っていた。2.1.286 の置き場所には無かったファイルである。探りの起動は約 10 秒・
  55,571 トークンだった（親の申告）
- **起動文の 13 個は一覧の写しである。** 今は利用者へ渡す手順のファイルに書いてあり、
  SKILL.md の一覧を変えても追随しない
- 親は自分のセッションの transcript の置き場所を知らない。CLI の利用枠の推定は
  `--transcripts ~/.claude/projects` を受け取る。探りの transcript をどう特定するか
  （起動の時刻・サブエージェントの ID）は決めていない
- 探りの起動は使用率を使う。利用枠の開始時点（`usage_gate.py --start`）の前に置くか後に
  置くかで、運用の消費に数えるかが変わる

## 裁定記録

- **起票**（2026-10-10・ユーザー）: 8g の回し直しの手順にある「準備の確認」の探りの文を、
  スキルの最初の確かめとして使う案を出した。エージェントが、判定を自己申告に置かない・
  名前を写さない・名前を測るものに合わせる、の 3 点を直す形を勧めた。ユーザーが、別に
  起票し、判定はスクリプトで照らす形にすると裁定した
