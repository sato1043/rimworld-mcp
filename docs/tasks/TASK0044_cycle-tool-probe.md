# サイクルに渡る tool の範囲を、無人の運用の前に確かめる

## 目的

無人で回す前に、サイクルのサブエージェントが、利用者の許可を要する tool とコマンドを
走らせる tool を実際に持っていないことを、運用のたびに確かめる。

TASK0018 の外側のループは、誰も確認しない間にサイクルを起こす。サイクルの定義
（`.claude/agents/rimworld-cycle.md`）は、持たせる tool を一覧で限り、ズルに当たる tool と
取り消せない操作の tool を除く。定義どおりに tool を絞るのは Claude Code の本体で、
絞り込みが効かなくなれば、無人のサイクルが `deconstruct` 等を呼べる。

## 目標（起票時の案）

- rimworld-autoplay の「始める前に」に、サイクルの定義を探りの起動文で 1 回起こす確かめを
  足す
- 判定はスクリプトが行う。サブエージェントの transcript から、本体が渡した tool の一覧と
  tool の呼び出しの結果を読み、除いた tool とコマンドを走らせる tool が無いことを照らす
  （ユーザー裁定 2026-10-10）
- 探りの起動文は、スクリプトが rimworld-play の SKILL.md の一覧から作る。名前をスキルの
  文へ写さない
- 照らせなかったとき（transcript が見つからない・一覧の記録が無い・形が読めない）は、
  合格にせず止まる
- 確かめが落ちたら、運用を始めずに利用者へ伝えて止まる
- TASK0018 の実機シナリオの「準備の確認」（利用者が起動文を手で渡す）を、この確かめで
  置き換える
- サイクルの Write と Edit の守り（TASK0040 の hook）が効いていることを、運用のたびに
  確かめる（裁定記録の「書ける範囲の守りの確かめ」）。確かめ方は決めていない（残課題）

## 非目標

- 除いた tool を実際に呼んで確かめること（呼べてしまったときに実害が出る）
- MCP の tool が動くかの確かめ（監視スクリプトの自己点検が持つ）
- サイクルの Write と Edit の届く範囲を決めること（TASK0040 が持つ）

## 問題

- **今の照合は実行時を見ていない。** `check_cycle_agent.py` は、サイクルの定義の
  `tools`・`disallowedTools` と、rimworld-play の SKILL.md の一覧と、`main.py` の tool を
  照らす。本体がその定義どおりに tool を渡すかは見ていない
- **スキルはその性質に寄りかかっている。** rimworld-autoplay の「始める前に」の 4 は
  「サイクルの定義が除いた tool は、許しても呼べない」と書く。確かめたのは、TASK0018 の
  「準備の確認」を手で回した回だけである（2026-09-29。8g の回し直しでもう 1 回回す）
- **本体の振る舞いは予告なく変わる。** サブエージェントの Write が `REPORT` 等で始まる
  名の `.md` を断ることは、実機で失敗するまで分からなかった（TASK0018 の裁定記録
  「報告のファイル」。2.1.283 と 2.1.286 で確かめた）
- **自己申告は判定に使えない。** 「準備の確認」の起動文は、13 個の名前が自分の tool の
  一覧にあるかをサイクル自身に答えさせる。09-29 に証拠として使えたのは、transcript の
  最初の `deferred_tools_delta`（`mcp__rimworld__*` が 77 個で、`main.py` の 87 個との差が
  除く 10 個と一致）と、`Bash` の呼び出しの失敗（「No such tool available: Bash」）
  だった。`PowerShell` と `Monitor` は呼び出しでは確かめていない
- **transcript の形は公開の仕様でない。** サブエージェントの transcript は
  `<セッション>/subagents/agent-<id>.jsonl` に在り、2026-10-04 の運用（2.1.286）の
  transcript にも `deferred_tools_delta` の `addedNames` が在る（2026-10-10 に 1 本を
  読んで確かめた）。形が変われば読めなくなるので、読めないときに止まる側へ倒す必要がある
- **呼び出しの失敗は、モデルが呼ぶかに左右される。** 2026-10-10 の「準備の確認」
  （2.1.293・`claude-sonnet-5-5`）では、サブエージェントが `Bash` は一覧に無いとして
  呼び出しを試みず、失敗の記録が残らなかった。同じ回のサブエージェントの置き場所には
  `agent-<id>.prefix.json` が在り、その `toolNames` が遅延でない tool の名前（7 個）を
  持っていた。2.1.286 の置き場所には無かったファイルである。探りの起動は約 10 秒・
  55,571 トークンだった（親の申告）
- **起動文の 13 個は一覧の写しである。** 今は利用者へ渡す手順のファイルに書いてあり、
  SKILL.md の一覧を変えても追随しない
- 親は自分のセッションの transcript の置き場所を知らない。CLI の利用枠の推定は
  `--transcripts ~/.claude/projects` を受け取る。探りの transcript をどう特定するか
  （起動の時刻・サブエージェントの ID）は決めていない
- 探りの起動は使用率を使う。利用枠の開始時点（`usage_gate.py --start`）の前に置くか後に
  置くかで、運用の消費に数えるかが変わる
- **書ける範囲の守りは、黙って外れうる。** TASK0040 は、サイクルの定義の hook で Write と
  Edit を方針ファイルに絞る。hook が走らなければ、書き込みは通る。TASK0040 が
  確かめるのは、実機シナリオを回した時点の版と設定だけである。外れる条件のうち
  分かっているものを挙げる。尽くしたとは言えない
    - フォルダの信頼が外れている。実測（2026-10-12・TASK0040 の作業記録「実機の探り」の
      回 7）: 承諾していない写しでは、同じ定義でも hook の応答が 1 件も無く、範囲の外への
      書き込みが 3 件とも通った。標準エラーにも何も出なかった
    - hook を切る設定が効いている。実測（2026-10-12・TASK0040 の「CP6 の後の回し直し」）:
      起動の引数 `--settings` で `disableAllHooks` を真にすると、hook の応答が 1 件も
      無く、範囲の外への書き込みが 4 件とも通った。設定ファイルに置いた場合と、組織の
      管理の設定 `allowManagedHooksOnly` は確かめていない
    - Claude Code の版が 2.1.295 より前である。守りのスクリプトが起動できない・時間切れ・
      終了コードが 0 と 2 のほか、のときに通る（公式ドキュメント。前の版では確かめて
      いない）
    - 同じ `name` の定義がもう 1 つ在る。読まれるのは 1 つで、どちらかは定まらない（公式
      ドキュメント）。`check_cycle_agent.py` は `.claude/agents/` の下だけを見る
    - 始める前に確かめた後で、定義が変わる・足される。`.claude/agents/` は見張られ、
      書き換えは次にサブエージェントを起こすときに届く（公式ドキュメント「Create custom
      subagents」。2026-10-12 取得）。起票時は「定義が読み直されない」ことを条件に挙げて
      いたが、逆だった。探りを運用の頭で 1 回だけ打つ形は、その後の起動を見ない
- **確かめ方で、見える条件が変わる。** 設定や版を読む方式は、上の一覧に無い条件を見ない。
  振る舞いを見る方式（書き込みを試す）は、条件を数えずに拾う（TASK0040 の CP6 の指摘。
  security M3）
- **書き込みを試す探りは、守りが外れていたときに書いてしまう。** 非目標の「除いた tool を
  実際に呼んで確かめること」と同じ向きの害がある。害の無い先（探り用のファイル）を選ぶか、
  書かずに hook の有無を読む口を探すかは、決めていない（残課題）
- **守りを入れる前から在るものは、守りが見ない。** TASK0040 より前のサイクルは、git の
  確かめの外（`.claude/settings.local.json` の hooks・`~/.claude`・`.git/config`・
  無視された `.claude/agents/*` と `.claude/skills/*`）へ書けた。TASK0040 は以後の
  書き込みを止めるが、すでに置かれたものが在るかは見ていない。`check_cycle_agent.py` が
  見るのは、`.claude/agents/` の下でサイクルの名を持つファイルだけである（TASK0040 の
  CP6 の指摘。security L4）
- **ToolSearch で届く tool が rimworld に限られることは、限られた構成でしか見ていない。**
  「サイクルの書き込みの口は Write と Edit の 2 つ」は、後から読み込む tool の一覧に、
  ほかの MCP サーバーの tool が入らないことに依る。TASK0018 の記録は、一覧が
  `mcp__rimworld__*` だけだったと書くが、その回の親にほかの MCP サーバーがつながって
  いたかを書いていない。hook の `matcher` は `Write|Edit` で、ほかの名の tool には
  当たらない（TASK0040 の CP6 の指摘。security-offensive M1。本体の振る舞いは確かめて
  いない）

## 裁定記録

- **起票**（2026-10-10・ユーザー）: 8g の回し直しの手順にある「準備の確認」の探りの文を、
  スキルの最初の確かめとして使う案を出した。エージェントが、判定を自己申告に置かない・
  名前を写さない・名前を測るものに合わせる、の 3 点を直す形を勧めた。ユーザーが、別に
  起票し、判定はスクリプトで照らす形にすると裁定した
- **書ける範囲の守りの確かめ**（2026-10-12・ユーザー）: TASK0040 の残課題「hook が効いて
  いることを、運用のたびに確かめるか」を、この作業で扱う（エージェントの推奨を採った）。
  探りの起動という同じ仕組みに乗るためである。非目標の 3 つ目を、範囲を決めることに
  限る形へ改めた
- **TASK0040 の CP6 からの追記**（2026-10-12・ユーザー）: TASK0040 の第三者視点レビューの
  指摘のうち 3 件（security M3・security L4・security-offensive M1）を、この作業書へ足す
  （エージェントの推奨を採った）。問題の節へ、守りが外れる条件の一覧・守りを入れる前から
  在るもの・ToolSearch で届く tool の測り方を足し、「定義が読み直されない」を正した。
  守りの確かめを持つことは、非目標の但し書きから目標へ移した
- **優先度**（2026-10-12・ユーザー）: `user-reach`・`dev-reach`・`irreversible`・
  `hazard` はエージェントの候補を承認した。`drive` は high と判定した

## stakeholder 未裁定の残課題

- 優先度の 4 軸と `drive`（裁定 2026-10-12）
- 書ける範囲の守りの確かめ方。害の無い先へ書き込みを試すか、書かずに hook の有無を読む
  口を探すか（問題の節）。前者は外れる条件を数えずに拾うが、外れていたときに書く
- 守りを入れる前から在るもの（設定の hooks・`.git/config`・無視された定義とスキル）を、
  この確かめで見るか、統合のときに利用者が 1 度見るか
- ほかの MCP サーバーをつないだ親から起こしたとき、サイクルの後から読み込む tool の
  一覧にそのサーバーの tool が入らないことを、この確かめで見るか
- 確かめる頻度（運用のたびに 1 回か、本体の版か定義が変わったときだけか）。起票時の案は
  運用のたびである
- 探りの起動を、利用枠の開始時点の前に置くか後に置くか
- `PowerShell` と `Monitor` を、一覧だけで確かめるか、呼び出しでも確かめるか
