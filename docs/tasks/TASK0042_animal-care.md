# 家畜の世話をサイクルで扱う

## 目的

家畜が飢えたり死んだりする状況に、サイクル（対話で遊ぶときも無人で回すときも）が
対応できるようにする。家畜の死亡を「入植者の死亡ではない」で見送らず、原因を見て
手を打つ。

## 目標（起票時の案）

- rimworld-play の手順が、家畜の飢え・死亡・頭数を割り込みか定期の確かめとして扱う
- 攻略知識に牧畜の要点（餌の干し草・ペットフード、放牧とペン、頭数と餌の釣り合い、
  屠殺）を持つ
- tool で出せない操作（屠殺の指定等）は、tool を足すか、利用者への頼み事として
  決まった形で出す

## 非目標

- ゲームの警告をサイクルへ見せること（TASK0018 のステップ 8f が扱う）
- 状況の変化からサイクルを起こすこと（TASK0037 が扱う）
- 動物の死亡の合図の振り分けを変えること（TASK0018 で受容した）

## 問題

- **手順が家畜の死亡を扱わない。** rimworld-play の手順 3 は `Death` を「入植者の
  死亡」に限る。2026-09-30 の無人の運用（TASK0018）では、14 回のサイクルがどれも
  家畜の死亡の letter を受け、どれも「入植者の死亡ではない」として指示を 0 件で返した。
  死因・飢え・頭数に触れた報告は無い
- **攻略知識に牧畜が無い。** `references/basics.md` に、家畜の餌・放牧・頭数の管理の
  記述が無い
- **頭数を減らす tool が無い。** 屠殺を指定する tool は無い。同じ運用で家畜は 342 から
  377 へ増え、「家畜が飢えている」（`Alert_StarvationAnimals`）が tick 35389565 から
  出続けた。死因が飢えかは確かめていない（推論）
- **起こされても手を打てない回が多い。** 2026-10-10 の無人の運用（TASK0018）では、
  前半の 39 サイクルのうち 24 回が家畜の死亡の letter だけで起き、
  どの回も対応は不要と判断した。優先度 Critical の家畜の警告（救助が要る・医療の緊急）
  も出続け、サイクルは「利用者に頼むこと」へ積んだ
- **出力が大きい。** 家畜の多いコロニーでは `get_animals` の出力が大きい
  （TASK0010）。頭数を見るたびに読むと、サイクルの文脈を圧迫しうる

## 裁定記録

- **起票**（2026-09-30・ユーザー）: TASK0018 の無人の運用で、家畜の死亡が続いても
  サイクルが手を打たなかった。「そもそも動物が死亡するような状況に対応できていない
  ことを示しており、対応できるようにするのが本質的」

## stakeholder 未裁定の残課題

- 屠殺を tool にするか、利用者への頼み事に留めるか
- 家畜の状況を割り込みで扱うか、定期の確かめで扱うか（TASK0037 との分担）
- 頭数の目安の決め方（餌の量から出すか、利用者が決めるか）
