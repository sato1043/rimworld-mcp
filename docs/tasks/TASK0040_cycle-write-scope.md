# サイクルが書けるファイルを方針ファイルに絞る

## 目的

無人で回すサイクルが書き換えられるファイルを、コロニーの方針ファイル
（`.claude/play/<コロニー名>/plan.md`）に限る。サイクルが、利用者の確認を経ずに実行の経路
（hooks・設定・スクリプト・状態のファイル）を書き換えられないようにする。

## 目標

- サイクルの Write と Edit が届くのは、方針ファイル
  （`.claude/play/<コロニー名>/plan.md`）だけである。届く範囲は許可リストで書く
- 範囲の外へ書こうとした呼び出しは、確認を求めずに断られ、サイクルは断られた理由を
  受け取る
- 守りが働かないとき（判定のスクリプトが起動しない・時間切れ）も、書き込みは通らない
- 範囲の守りを外すと落ちる検査を持つ。判定の中身と、定義の hook の指定の
  2 面を見る

## 非目標

- ゲームの tool の範囲（TASK0018 の許可リストと除く一覧が受け持つ）
- 対話で遊ぶとき（`rimworld-play` を直に使うとき）の権限
- サイクルの Read・Glob・Grep が読める範囲
- 親のセッションの権限と、親が打つ git の確かめの変更（そのまま残す）
- 状態のファイルとステータスラインの記録の置き場所を移すこと（裁定記録の「状態の
  ファイルの置き場所」）
- ステータスラインの記録の読み方の変更。この作業は、記録へ書ける者からサイクルを外す
  ところまでとする

## 問題

- **サイクルは方針ファイルを書くために Write と Edit を持ち、どのファイルにも書ける。**
  TASK0018 は、親がスクリプトを走らせる前と Monitor を張る前に毎回、`.claude/agents`・
  `.claude/skills`・`mcp_server` の `git status --porcelain --untracked-files=all` を
  打ち、1 行でも出たら止まる形で受けている
- **git の確かめの外に、実行の経路が残る。** TASK0018 の自己コードレビューで挙げた
    - 追跡の外の設定: `.claude/settings.local.json` の hooks
    - `~/.claude` の hooks と設定
    - `.git/config`（`git status` 自身が `core.fsmonitor` を走らせる）
    - `__pycache__`（書き換えた `.pyc` が次の `uv run` で読まれうる）
    - 状態のファイル: `usage.json`（上限）・`cycle.json`（印）・`watch.json`（監視の位置）
- **無視されたファイルは git の確かめに現れない。** `.gitignore` は `/.claude/agents/*`
  と `/.claude/skills/*` を除外し、サイクルの定義と 2 つのスキルだけを例外にしている。
  サイクルが新しい定義やスキルをそこへ書いても、`git status` は出さない（`.gitignore` の
  行から読んだ。書いて確かめてはいない）
- **範囲を絞る仕組みは確かめていない。** サブエージェントの定義の `tools` は tool の名前を
  選ぶが、書けるパスは選ばない。permission の規則（パスつきの `Write(...)`）や hook が
  バックグラウンドのサブエージェントにどう効くかは、公式ドキュメントと実機で確かめる
  必要がある
- **ステータスラインの記録の置き場所の境界は、権限の実体では引かれていない。** TASK0018 の
  ステップ 9 は、CLI の判定が読む記録を `.claude/play/` の外
  （`.claude/rate-limits.jsonl`）へ置いた。当時のスキルが示した許可の規則は
  `Edit(/.claude/play/**)` だが、Auto モードでは内も外も同じ classifier の判定になると
  公式ドキュメントから読める（TASK0018 の 2026-10-11 の CP6。classifier の振る舞いは
  実機で見ていない）。記録は追跡の外で、git の確かめにも出ない
    - 記録へ書ける者は、低い値の行を最後に足して起こせる。最後の行が別の 5 時間枠を
      名指すと、新しい行のうち最も高い値を採る規則が働かない（同じ CP6 の再評価層が、
      80 と 85 の後に別の枠の値 1 の行を足して起こす側を再現した）
    - 上限（`usage.json` の `limit`）は `.claude/play/` の内に残るので、記録を外へ出した
      効果は、上限を書き換えられると打ち消される（上の「状態のファイル」と同じ点）
- **ステータスラインは、親の git の確かめを経ずにスキルのコードを走らせる。** CLI の
  準備で `statusLine` を足すと、`record_rate_limits.py` と `usage_rules.py` が
  60 秒ごとに、利用者のセッションの権限で走る。サイクルがこの 2 つを書き換えると、
  親が次の合図で git を打つ前に走りうる（同じ CP6。書き換えて確かめてはいない）

以下は 2026-10-12 の分析で足した。出典は、Claude Code の公式ドキュメント「Create custom
subagents」「Configure permissions」「Hooks reference」（同日に取得）と、このリポジトリの
スクリプトである。

- **サイクルの書き込みの口は Write と Edit の 2 つである。** 定義の `tools` はコマンドを
  走らせる tool を持たず、`check_cycle_agent.py` が一覧の一致を見る。バックグラウンドの
  サブエージェントにも Write と Edit は残る（公式ドキュメント）
- **サイクルが書くのは方針ファイル（`plan.md`）だけである。** 状態のファイルは親が走らせる
  スクリプトが書く（`cycle.json` は `check_plan.py`、`usage.json` は `usage_gate.py`、
  `watch.json` は `watch.py`）。定義の本文は、報告のファイルを書かないと定める
- **定義の `tools` と `disallowedTools` は、tool の名前を選ぶだけである。** パスつきの
  指定を書いても、その tool ごと外れる（公式ドキュメント）
- **permission の規則はサイクルだけに当てられない。** 規則はセッションの全体に効き、親と
  開発のセッションの Edit も止める。評価は deny・ask・allow の順で、allow は deny の例外を
  切り出せない（公式ドキュメント）
- **定義の frontmatter の hook は、そのサブエージェントが動く間だけ走る。** PreToolUse の
  hook が終了コード 2 を返すと呼び出しは止まり、stderr がサブエージェントへ返る。
  プロジェクトの定義の hook は、フォルダの信頼を承諾した後にだけ走る（公式ドキュメント。
  バックグラウンドのサイクルで実際に走るかは、実機で確かめていない）
- **hook は、起動に失敗すると通す側へ倒れる。** 終了コードが 0 と 2 のほか（スクリプトが
  見つからない 127・例外の 1）と時間切れは、呼び出しを止めない。止める側へ倒す指定
  （`onFailure` の `block`）は Claude Code 2.1.295 以降にある（公式ドキュメント）。この
  機械の CLI は 2.1.296 である（2026-10-12 に `claude --version` で見た）。デスクトップ
  アプリの版は確かめていない
- **定義の置き場所は見張られ、書き換えは数秒で次の起動に届く。** `.claude/agents/` の
  定義を書き換えると、動いているセッションも次にそのサブエージェントを起こすときに新しい
  定義を読む（公式ドキュメント「Create custom subagents」。2026-10-12 に取り直した。当初は
  「セッションの開始のときに読まれる」と書いていたが、誤りだった）。同じ木に同じ `name` の
  定義が 2 つ在ると、読まれるのは 1 つで、どちらかは定まらない（同じドキュメント）
- **定義を読む関数は、入れ子の形を読まない。** `cycle_agent.frontmatter` が読むのは、値・
  折り返した値・1 段の一覧だけで、ほかの形は `FrontmatterUnreadable` で断る。hook の指定は
  入れ子なので、そのまま足すと `check_cycle_agent.py` が UNTRUSTED を返し、`agent_model`
  を読む側も止まる

## 概要設計

### 全体の構成

守りは 3 つの部品から成る。

1. **判定の関数**（`write_rules.py`）: パスを受け取り、許すか、断る理由と種別を返す。
   ファイルシステムを読む（リンクをたどる・方針ファイルが在るかを見る）が、何も書かない
2. **入口**（`write_gate.py`）: hook が渡す JSON を標準入力から読み、判定の関数へ渡し、
   終了コードで答える
3. **hook の指定**（`.claude/agents/rimworld-cycle.md` の frontmatter）: Write と Edit の
   前に入口を走らせる

置き場所は `rimworld-autoplay` の `scripts/` とする。判定と入出力を分ける形は、同じ
ディレクトリの `watch_rules.py` と `watch.py`、`usage_rules.py` と `usage_gate.py` に
そろえる。スクリプトは追跡下に在り、親の git の確かめの内側にある。方針ファイルでは
ないので、サイクルは守りそのものを書き換えられない。

### 判定の関数

- 許すのは、解決した先が `<PLAY_ROOT>/<コロニー名>/plan.md` に等しく、そのファイルが
  すでに在るパスだけである。`PLAY_ROOT`・`PLAN`・`colony_name_problem` は
  `play_files.py` のものを使う
- 判定は等号で書く。親が `PLAY_ROOT` に等しく、その 1 つ下がコロニー名で、ファイル名が
  `plan.md` に等しいことを見る。「この下なら許す」の形にしない
- 名前の比べ方は 1 つにそろえる（`same_name`）。Windows では大文字と小文字を同じに扱い、
  ほかでは区別する。親の比較と同じ pathlib の等号である
- ファイルシステムへ問う前に、字面で 2 つを断る
    - 最後の要素が `plan.md` と書かれていないパス。末尾の `.` や空白・`plan.md::$DATA`・
      `plan.md:stream` は、Windows が方針ファイルと同じファイルとして開くことがあるが、
      断る。同じファイルを指す表記を断ることになるが、守りの向きには安全な側である
    - ほかの機械の共有とデバイスのパス（Windows でドライブが `\\` で始まるもの）。
      解決を呼ぶと、断る前にその先へ問い合わせが出るためである。`PLAY_ROOT` 自身が共有の
      上に在るときの、その共有だけは見る
- そのうえで、パスを解決する。相対パスは hook の入力の `cwd` から解き、`..` と
  リンク（ジャンクションを含む）をたどった先で比べる。解決した先のファイル名も見る
  （方針ファイルの名を持つリンクが、ほかのファイルを指す場合のため）
- 解決できないパス・空のパスは断る
- 在らない方針ファイルは断る。サイクルは方針ファイルを作らない（定義の本文「無ければ
  作らずに返す」）。在ることを見るので、存在しない別の木を指すパスは通らない
  （U+212A のように、小文字にすると `k` になるがファイルシステムでは別の名になる文字で
  書いたパスを含む）
- 断る理由は種別を持つ（`Kind`）。ほかのファイル・在らない方針ファイル・読めないパスの
  3 つで、入口が種別ごとに次の動きの文を付ける。理由は種別を分ける語で始まり、パスは
  その後ろに置く。サイクルが親へ運ぶのは理由の頭だけで、パスはどんな語も含みうるため
  である
- 理由へ埋めるパスと例外の文は、引用符で囲み、印字できない文字を逃がし、200 字で切る
  （`shown`）。サイクルがパスへ入れた改行や文が、理由の行として読まれないためである
- 残る性質: 割り当て済みのネットワークドライブ（ドライブ文字を持つ共有）は、字面では
  見分けられず、解決の段で問い合わせが出る。8.3 の短い名で書いたパスは測っていない

### 入口

- 標準入力の JSON から `tool_name` と `tool_input.file_path` を読む。`tool_name` が
  Write と Edit のほかなら断る（hook の指定の `matcher` が広がったときに、通す側へ
  倒れないため）
- 許すときは何も出さずに 0 を返す。断るときは理由を stderr へ 1 行で出し、2 を返す。
  行は `refused:` で始まり、理由と、次の動きの文を持つ。次の動きは断りの種別で変わる
    - ほかのファイル: 書き直さず、利用者の操作が要ることは「利用者に頼むこと」へ積む
    - 在らない方針ファイル: 何も書かない（方針ファイルは利用者が作る）
    - 読めないパス: ほかへ書かない。方針ファイルのつもりなら、絶対パスで名指す
    - 入口が判定できなかったとき（読めない入力・Write と Edit のほかの tool・例外）:
      どのファイルも書けない。方針ファイルへ送らない。理由は `the write gate is broken`
      で始め、起きたことの文は 1 行に収めて 200 字で切る
- 読めない入力と、判定の途中の例外は、2 を返す。例外をそのまま落とすと終了コードが 1 に
  なり、呼び出しが通る
- 標準ライブラリだけで書く。hook は `uv` の環境を通さずに走る。入口が読み込む
  `write_rules.py` と `play_files.py` にも同じ制約が掛かる。テストは入口を `-S`（site の
  パッケージなし）で起こすので、外のパッケージを import すると落ちる

### hook の指定

定義の frontmatter へ次を足す。

```yaml
hooks:
  PreToolUse:
    - matcher: "Write|Edit"
      hooks:
        - type: command
          command: python
          args:
            - "${CLAUDE_PROJECT_DIR}/.claude/skills/rimworld-autoplay/scripts/write_gate.py"
          timeout: 10
          onFailure: block
```

- プログラムと引数を分ける形（`command` と `args`）で書く。公式ドキュメントが、パスの
  置き換え（`${CLAUDE_PROJECT_DIR}`）を使う hook に勧める形で、シェルを通さない
- `onFailure` の `block` は、入口が起動できないとき・時間切れのとき・終了コードが 0 と
  2 のほかのときに、呼び出しを止める側へ倒す。置き場所は、走らせるコマンドの側である
  （`matcher` の塊の側に置くと読まれない）
- `python` は、スキルがステータスラインの設定に使う名とそろえる。PATH に無い機械では
  hook が起動できず、`onFailure` が書き込みを止める。サイクルは方針ファイルを書けなく
  なり、その理由を返す（止まる側に倒れる）
- `timeout` の 10 秒は、入口の所要（PATH の `python` 3.13.4 で 0.10〜0.15 秒・7 回）の
  約 70〜100 倍である

### 定義を読む関数と照合器

- `cycle_agent.frontmatter` に、入れ子の塊をそのままの行として持つ形を足す。当たるのは
  名前で決めたキー（`KEPT_AS_LINES`。今は `hooks` だけ）で、値が空のときである。その
  キーは、1 段の一覧も行のまま持つ。中身は解釈しない
- 期待する指定を 1 か所の定数に置く。`check_cycle_agent.py` は、定義の `hooks` の塊が
  その定数と等しいことを見る。等号で見るので、外す・`matcher` を狭める・`onFailure` を
  外す・別のスクリプトを指す、のどれも落ちる
- `hooks` のほかのキーが入れ子の形を持つときは、今までどおり断る
- 行の中に `---` を含む frontmatter は断る。定義を走らせる側がそこで frontmatter を終え、
  その下の `hooks` を読まないおそれがあり、照合器だけが `hooks` を見ることになる。
  開きと閉じは、`---` だけの行に限る（前後に空白の付いた行は断る）
- 照合器の等号は、自前の読み方の上の一致である。Claude Code は自分の YAML の読み手で
  定義を読むので、2 つの読みが割れる書き換えは、照合器を通ったまま実効の定義を変える。
  割れ方のうち分かっているものを、読む関数が断る
    - 行の終わりは LF・CR・CRLF だけとする。`str.splitlines()` は U+2028 等でも行を割り、
      YAML では続きの行になる（`#` の後ろへ置くと、下のキーがコメントの続きになる）
    - 空白は半角の空白だけとする。印字できない文字と、ほかの空白（U+00A0・U+3000・タブ）は
      断る。`strip()` はこれらを落とすが、YAML では値の一部になる
    - 引用符で始まる値は、その行で閉じ、内側に同じ引用符を持たないものだけを読む。
      閉じない引用符は、YAML では下の行（キーを含む）を値へ取り込む
    - この読み方が知らない YAML の形（タグ・アンカー・別名・波括弧・指示子つきの
      block scalar 等）で始まる値は断る
- 照合器は、定義の最上位のキーを期待の集合（`KEYS`。今の 8 つ）と等号で照らす。照合器が
  見ないキー（`permissionMode` 等）を足した定義は通らない。`name` が定義の名であることも
  見る
- 照合器は、定義と同じディレクトリの木（`.claude/agents/` の下。無視されたファイルを
  含む）に、サイクルの名を本文のどこかに持つ別のファイルが在れば 1 を返す。定義として
  読めないファイルも Claude Code は読みうるので、定義として読まずに文字列で探す。
  引用符の中のエスケープで名を書いたファイルは見つからない
- 残る性質: Claude Code 自身が定義をどう読むかは、実装が公開されておらず測れない。
  上の割れ方は Python と YAML の仕様の差から拾ったもので、尽くしたとは言えない

### 定義の本文とスキルの手順

- 定義の本文: Write と Edit が断られたら、ほかのファイルへ書き直さず、返す 1 行に
  断られたことを含める。方針ファイルへの書き込みが断られたら、理由が何であっても、
  ゲームが走っていれば止め、止めたまま返す。サイクルは原因を見分けない。返す行は
  「方針ファイルを書けなかった」で始め、頼みたかったことと、返った理由の頭 400 字を運ぶ。
  400 字は、Claude Code が理由の前に付ける前置き（2.1.296 で 116 字）・種別を分ける語・
  200 字までのパスが収まる長さで、テストが留める
- スキルの「始める前に」: 書ける範囲が方針ファイルだけであること・フォルダの信頼の承諾が
  要ること・Claude Code が 2.1.295 以降であること・`python` の名で Python 3.13 以降が
  起動できることを足す。開始のときに照合器（`check_cycle_agent.py`）を走らせる
- スキルの「方針ファイルを書けなかったとき」: 親は、その行が返ったら運用を止め、返った
  理由を表で読んで直し方を伝える。原因を見分けるのは、人が読むスキルの側である。
  守りのスクリプトが断った理由は、最初の `refused:` に続く語で読む（その後ろのパスに
  同じ語が在っても読み違えない）。その語は定数に置き、テストが表と結ぶ。`refused:` の
  無い理由は Claude Code と `python` の文言で読む。この 2 つは結べないので、表にそう書き、
  知らない文言でも hook が止めたことだけは読める行を置く
- スキルが示す許可の規則の例から、`Edit(/.claude/play/**)` の行を削る。`.claude/` の下は
  Claude Code が守るパス（protected paths）で、許可の規則では事前に許せない（作業記録
  「実機の探り」）。スキルは、無人では Auto モードで回すことと、Manual モード（設定の
  値は `default`）ではサイクルが書くたびに確認が出ることを書く（裁定記録の「許可の規則の
  例とモードの案内」）

### 選ばなかった案

- **permission の deny の規則**: サイクルだけに当てられず、方針ファイルだけを例外にも
  できない（問題の節）
- **状態のファイルを別のディレクトリへ移す**: 許可をファイル名で書けば、同じディレクトリに
  在っても届かない。移すと、親のスクリプト 3 本と手順の置き場所が変わる
- **設定ファイルの hook**: セッションの全体で走るので、サイクルかどうかを入力の
  `agent_type` で見分ける分岐が要る。定義の hook は、定義と一緒に動き、ほかの
  セッションに触れない

### 書き留めておく性質

- 絞るのは書き込みだけである。サイクルは今までどおり、どのファイルも読める
- 許すのは、すでに在る、どのコロニーの方針ファイルもである。開いているサイクルの
  コロニーに限らない（裁定記録の「コロニーの絞り込み」）
- hook が効いているかを、運用のたびに確かめる口は持たない。TASK0044 が持つ（裁定記録の
  「運用のたびの確かめ」）。この作業が確かめるのは、実機シナリオを回した時点の版と
  設定である
- 親の git の確かめは残す。追跡下のスクリプトを書き換える者はサイクルだけではない
- リンクを要する抜け道（ハードリンク・POSIX で `..` の前にリンクを置く形）は、サイクルが
  リンクを作る tool を持たないことに依る。持つ tool は照合器が等号で留める
