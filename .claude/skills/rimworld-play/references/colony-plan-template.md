# コロニー方針ファイルの雛形

置き場所と、置く前に確かめることは [../SKILL.md](../SKILL.md)「始める前に」に従う。この
ファイルは git で追跡しない（`.gitignore` の `/.claude/*`）。サイクルの初めに読み、
終わりに書く。

節の意味は次のとおり。節を増やしてよいが、ここにある節は消さない。「計画」と「運営」は
子の節を束ねる見出しで、その下に項目を書かない。

- **利用者に頼むこと**: tool に無い操作・選択肢のある letter・許可の要る tool のうち、
  利用者がまだ片付けていないもの。急ぐものから並べ、片付いたら消す
- **環境**: セーブ全体の前提。ゲームの版と DLC・Mod・ストーリーテラーと難易度・マップ。
  作るときに [../SKILL.md](../SKILL.md)「環境を調べる」のとおりに調べて書く。無人の
  サイクルは書き換えない
- **計画**: 長い間に変えない判断
    - **長期方針**: クリアの経路（自分で建てる宇宙船・クエスト「宇宙への旅」）と、
      コロニーの性格（守りを固める・交易で稼ぐ等）。めったに変えない
    - **研究の道筋**: 研究の予定の順。`set_research` へ渡す defName で書く
    - **クリアの計画**: 必要な研究・資材・部品の進み具合
    - **基地の配置**: 住居・倉庫・冷凍庫・畑・防衛線の範囲。座標は `(x, z)` の順で、範囲は
      向かい合う 2 隅を `(x1, z1)〜(x2, z2)` と書く。`get_cells_info` で見た範囲を書く
- **運営**: サイクルごとに書き換える判断。rimworld-play の手順 4 と 6 が 3 つを一緒に扱う
    - **次にやること**: 次のサイクルで確かめること・指示すること
    - **進行中の対応**: 途中の対応ごとに、何を・なぜ・終わる条件・次に確かめること（例:
      「北の防衛線に 3 人を徴兵して待たせている: 襲撃に備える。終わる条件: 敵が去る。次に
      確かめること: 負傷者」）。
      ゲームの状態に現れない途中（襲撃に備えて徴兵して待たせている等）を、次のサイクルへ
      渡す。1 つの対応を 1 つの項目にし、新しい対応は新しい項目として書く（古い項目へ
      書き足さない）。終わる条件を満たしたら項目を消す。対応が無ければ節を空にする
    - **前提と根拠**: 判断ごとに、その前提・根拠（何を見たか）・見直す条件（例: 「狩りを
      止めた: 前提は食料が 10 日分あること。根拠は `get_colony_overview`。見直す条件: 5 日分を
      切る」）。見直す条件を満たしたか、前提が崩れて判断を改めたら、古い項目を消し、理由を
      「経過のメモ」へ書く
- **開発者向けの書き足しの候補**: 攻略知識の候補の文面。承認済みは開発のセッションが
  スキルへ反映し、反映したら消す。保留は次のセッションで改めて示す
- **出来事の位置**: 最後に `get_events` が返した `next`。次のサイクルで `since` に渡す
- **経過のメモ**: 日付（ゲーム内）ごとの出来事・方針を変えた理由・ズルに当たる tool の
  許可。収束した事柄（終わった対応・片付いた頼みごと・確かめ終えた疑い等）は、経緯を
  消して結果だけを 1 行に残す。収束していない事柄の経緯は残す。1 回のサイクルの項目は
  2 行までとし、前の項目から変わっていない読みは書かない。前の項目と同じ判断で指示も
  出さなかったときは、項目を足さずに、前の項目の時点を範囲へ延ばして回数を添える

「進行中の対応」の各項目は「終わる条件:」の欄を、「前提と根拠」の各項目は「見直す条件:」
の欄を必ず持つ。項目は行頭の箇条書き 1 つで、その下の行と入れ子の箇条書きを含む。
1 つの項目の欄は、すべてその 1 つの箇条書きの中に書く（欄ごとに行頭の箇条書きを分け
ない）。無人で回すとき、方針ファイルの照合が欄の有無を見る（中身は見ない）。
「なし」のような欄を持たない項目や、節の下に書いた地の文も、欄が無いと数える。下の
コードブロックの 2 節にある `<…>` の項目は欄の形の見本で、方針ファイルを作るときに消す。
残すと、照合は見本の項目として落とす。
