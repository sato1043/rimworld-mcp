# mcp-rimworld（日本語の案内）

LLM が [Model Context Protocol](https://modelcontextprotocol.io/) を通して、動いている
RimWorld を操作する。

このファイルは、この fork（`sato1043/rimworld-mcp`）が持つ Claude Code のスキルの使い方を
書く。Mod のビルド・MCP サーバーの登録・tool の一覧は [README.md](README.md)（英語）に
ある。

## スキル

| スキル | 役割 |
|---|---|
| `rimworld-play` | 利用者と対話しながら、コロニーを 1 サイクルずつ運営する |
| `rimworld-autoplay` | 利用者が手番ごとに進めなくても、コロニーを回し続ける |

対象は RimWorld 1.6・DLC なしである。スキルは `.claude/skills/` にあり、このリポジトリで
Claude Code を起動すると読み込まれる。

## 準備

1. [README.md](README.md) の Setup の 1〜3 を済ませる（Mod のビルド・`Mods` へのリンク・
   MCP サーバーの登録）
2. ゲームのオプションで「バックグラウンド実行」（英語の画面では Run in background）を
   有効にする。無効だと、ゲームの窓が裏にある間の要求が 15 秒で失敗する
3. ゲームでセーブを読み込む
4. このリポジトリの本体のチェックアウトで Claude Code を起動する。`git worktree` で足した
   作業ツリーでは、スキルは止まる。コロニーごとのメモを本体の `.claude/play/` に置くため
   である

## 1. 方針ファイルを作る

方針ファイル（`.claude/play/<コロニー名>/plan.md`）は、コロニーごとのメモである。長期の
方針・進行中の対応・経過のメモを持ち、スキルがサイクルごとに読んで書き換える。git は
追跡しない。

次のように頼む。`<コロニー名>` は自分のコロニーの名前に置き換える。

```
<コロニー名>の方針ファイルを雛形から作り直して
```

`rimworld-play` が雛形から方針ファイルを作る。書く前に環境を調べる。

- マップは tool で読む
- Mod の一覧は、ゲームの設定ファイル（`ModsConfig.xml`）から読む
- ストーリーテラーと難易度は読む手段が無いので、利用者に尋ねる

コロニー名は tool から読めないので、利用者が決める。名前はディレクトリ名になる。既に
方針ファイルがあるコロニーでは、作り直しになる。古いファイルをどう扱うかはスキルが
決めていないので、残したいときは頼む文に書く。

作った直後の「長期方針」は空である。クリアの経路や研究の道筋を対話で決めて書いておくと、
何も起きていないときのサイクルが、照らす先を持てる。

## 2. 無人で回す

次のように頼む。

```
rimworld-autoplay で「<コロニー名>」を無人で回して。5 時間枠の上限は 33。権限は Auto モードで回す。バックグラウンド実行は有効化済み
```

後ろの 3 つの文は、スキルが始める前に尋ねる事柄への答えである。書かなければスキルが
尋ねる。

| 文 | 意味 |
|---|---|
| 5 時間枠の上限は 33 | サブスクリプションの 5 時間枠の全体がこの割合（%）に達したら、次のサイクルを起こさずに止まる。ほかの仕事に残す分を引いて決める。誰が使った分かは問わず、今の値が既にこの値以上なら始まらない。週の枠は判定しない |
| 権限は Auto モードで回す | 無人の間に権限の確認が出ると、サイクルはそこで止まる。Auto モードで回す。Manual モードでは、サイクルが方針ファイルを書くたびに確認が出て、許可の規則では止められない |
| バックグラウンド実行は有効化済み | 準備の 2 のゲームのオプションを済ませたこと |

スキルはこのほかに、読み込んでいるセーブがそのコロニーのものか・共有の秘密・自動の要約の
窓を確かめる。確かめが済んだら、次のようにして離れる。

- ゲームのポーズを解く。ポーズのままだと、利用者が止めたとみなして何も起こさない
- 最初のサイクルが、権限の確認で止まらずに戻るのを見る

止めるときは、そのセッションに「止めて」と頼む。

### 動き方

- 監視スクリプトがゲームを 1.5 秒ごとに読む。この読み出しは LLM を通らない
- 襲撃・死亡などの letter と優先度の高い警告が出ると、ゲームを止めてサイクルを起こす。
  敵がいる間は短い間隔で起こし、何も無ければゲーム内の 1 日ごとに見回る
- 1 サイクルはサブエージェントが行う。観察して指示を出し、方針ファイルを書いて、
  ゲームを再開する
- 選択肢のある letter のように tool で答えられないものは、ゲームを止めたまま利用者へ
  知らせる

### 知っておくこと

- 利用枠を使う。サイクルを 1 回起こすごとに消費するので、出来事の多いコロニーほど早く
  上限に届く
- デスクトップアプリの Code タブで回す。CLI で回すには、使用率をステータスラインから
  記録する設定（`statusLine`）を、本体のチェックアウトの `.claude/settings.local.json` に
  足す必要がある。形は、開始が断られたときにスキルが示す。CLI の経路を実機で確かめたのは
  Windows（Git Bash）の 1 回で、ほかの OS とシェルでは確かめていない
- ズルに当たる tool と取り消せない tool は、無人のサイクルからは呼べない
- 無人のサイクルが書けるファイルは、コロニーの方針ファイルだけである。サイクルの定義の
  hook が、ほかの書き込みを止める。この守りが働くには、本体のチェックアウトのフォルダの
  信頼を承諾してあること・Claude Code が 2.1.295 以降であること・`python` の名で
  Python 3.13 以降が起動できること（`uv` の環境とは別）・hook を切る設定
  （`disableAllHooks`）が効いていないことが要る。スキルが始める前に確かめる
